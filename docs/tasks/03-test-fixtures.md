# 03 — Test fixture library and the real-path guard

- **Phase:** M1 · Trustworthy move engine
- **Depends on:** 01, 02
- **Status:** done

## Goal

A builder that materializes a realistic throwaway music library in a temp
directory, so every later task can be tested against the ugly cases instead of
a clean one. Plus a hard guard that no test can touch the real `~/Music` or
`~/.config/mpd`.

## Details

As built. The sketch this task started from took `(genre, album)` pairs; one
`dir` relative to the music directory turned out to say the same thing without
pretending the library is only ever two levels deep.

```rust
let fx = Fixture::builder()
    .album("hiphop/MF DOOM - Mm..Food (2004) [V0] scene-tag", &["01 Beef Rap.mp3", ..])
    .aux("hiphop/MF DOOM - Mm..Food (2004) [V0] scene-tag", &["folder.jpg", "info.nfo", "x.sfv"])
    .multi_disc("pop/Imagine Dragons - … (2 CD) …", &["CD 1 - …", "CD 2 - …"])
    .non_ascii_album("electronic/KREAM - So Hï [c0D2h71bFFI]")
    .flac_album("jazz/Miles Davis - Kind of Blue (1959) [FLAC]")
    .track("single.mp3")                             // a track with no album dir
    .playlist("Hip hop.m3u", &["hiphop/…/01 Beef Rap.mp3", "", "# comment"])
    .playlist_with_urls("Radios.m3u", &[])            // #EXTM3U, comments, #EXTINF, http URLs
    .playlist_raw("Crlf.m3u", b"#EXTM3U\r\npop/a.mp3\r\n")   // CRLF, BOM, no trailing newline
    .symlinked_playlist("Radios.m3u", DOTFILES_PLAYLISTS)  // dir relative to the fixture root
    .cue_reference("pop/…/CD 1 - …", "album.flac.cue/track0017")
    .broken_reference("Pop.m3u", "pop/gone/missing.mp3")
    .state_file_queue(&["electronic/…/01 So Hï.mp3", ..])   // N:relpath lines
    .non_utf8_file("electronic", b"So H\xEF.mp3")     // opt-in; task 05 needs it
    .build();

Fixture::realistic()                 // all of the above, as `PLAN.md` §3 describes it

fx.music_dir()  fx.playlist_dir()  fx.state_file()  fx.data_dir()  fx.root()
fx.abs("hiphop/…/01 Beef Rap.mp3")   fx.rel(..)   fx.playlist_path("Radios.m3u")
fx.tracks()  fx.aux_files()  fx.playlists()  fx.cue_references()  fx.broken_references()
fx.snapshot()          // paths + modes + symlink targets + text verbatim + audio digests
fx.assert_inside(&path)   fx.assert_all_inside(paths)   fx.contains_path(&path)
fx.flip_byte(&path)    // one-byte change, for proving a check notices
names::MF_DOOM_TRACK, names::MERCURY_CUE_TRACK, …   // the long scene names, typed once
```

Real audio files: five committed under `crates/core/tests/data/`, generated by
`generate.sh` with `ffmpeg -f lavfi -i "sine=…"` and carrying real ID3v2.3,
ID3v2.4, Vorbis and MP4 tags, so tag tests (16–18) can use the same fixture
without `ffmpeg` being installed.

`fx.snapshot()` is the workhorse for undo tests: commit → undo → snapshots must
be equal. `Snapshot::assert_same` prints only the paths that differ.

## Acceptance criteria

- [x] `Fixture::build()` produces a tree with: non-ASCII names, spaces,
      brackets, `&`, `+`, an apostrophe, a multi-disc album, aux files, a FLAC
      album, a symlinked playlist, a CUE virtual-track reference, a radio-URL
      playlist, and one deliberately broken reference
- [x] the fixture is deleted when dropped, and nothing is left in `/tmp` after
      `cargo test`
- [x] a guard function asserts every path an operation touches is inside the
      fixture; a test proves the guard fires when handed `~/Music`
- [x] `snapshot()` detects a one-byte change in any audio file or playlist
- [x] fixture construction takes < 2 s so tests stay fast — measured at
      **0.26 ms** for 47 entries; `snapshot()` costs 0.21 ms

## Files

`crates/core/src/testing/{mod.rs,audio.rs,snapshot.rs}`,
`crates/core/tests/data/` (five committed audio templates, `generate.sh`,

## Decisions

**A `testing` feature, enabled by a dev-dependency on ourselves.** `#[cfg(test)]`
alone would not reach `tests/`, and a separate `mpdfm-test-support` crate would
be a third package to keep in step. `mpdfm-core = { path = ".", features =
["testing"] }` in `[dev-dependencies]` means `cargo test` needs no extra flag
while `cargo build --release` carries neither the module nor `tempfile`,
`walkdir` or the embedded audio (verified: core's release dependency tree is
`camino` + `thiserror`).

**Audio is committed, not generated.** Five ffmpeg-produced sine waves of
0.2–0.3 s, 730–2 378 bytes each, with real ID3v2.3, ID3v2.4, Vorbis and MP4
tags, embedded with `include_bytes!`. Tests therefore never need `ffmpeg` and
never depend on the working directory. `tests/data/generate.sh` regenerates them;
`tests/data/README.md` lists what each one is for and which tag cases are
deliberately still missing (a multi-valued FLAC `ARTIST`, a numeric `TCON`) —
those need a tag *writer*, so tasks 16–18 should add them.

Every track of a format is byte-identical to every other, which is what makes
snapshot comparison meaningful but means content cannot distinguish two tracks.
`Fixture::flip_byte` exists for tests that need a difference.

**`Fixture::builder()` is empty; `Fixture::realistic()` is the whole library.**
The acceptance criterion above describes `realistic()`, which composes the
builder into the library of `PLAN.md` §3 — 17 tracks, 4 playlists, 47 entries.
Tests that want one album build one, and pay for one.

**Layout inside the temp root** mirrors the real *relationships* rather than the
real paths: `music/`, `playlists/`, `mpd/state`, `data/`, and
`dotfiles/mpd/playlists/` as the symlink target — outside the playlist directory,
inside the fixture, so the containment guard still holds.

**The guard is `paths::contains` plus a real-library check.**
`Fixture::assert_inside` (and `assert_all_inside`) delegates to task 02's
`contains`, so the guard tests exercise the same code the commit path will, and
adds a lexical check against `~/Music`, `~/.config/mpd`, `~/.local/share/mpdfm`
and the `XDG_*` equivalents purely so the panic message can say *this is the real
library*. `real_library_roots()` is public and built from the environment; the
builder also refuses to start if `$TMPDIR` itself points into the real library.

**Snapshots record contents, modes and symlinks — not mtimes.** Restoring a file
byte-for-byte gives it a new mtime, so an mtime-sensitive snapshot would fail
every undo test for the wrong reason. Text files (playlists, the state file,
`.cue`, `.nfo`) are kept verbatim so a failure prints the offending line; audio is
size plus an FNV-1a-64 digest. Symlinks are recorded *as* symlinks with their
target, which is what catches the task 06 trap of replacing `Radios.m3u` with a
regular file. Targets inside the tree render as `<root>/…`, so the rendering is
stable enough for `insta`. Compare with `Snapshot::assert_same`, which prints only
the paths that differ.

## Pitfalls

- Build this *before* the move engine, not after. It is the only reason the
  later tasks can be verified rather than hoped about.
- Don't gate on `ffmpeg` being installed at test time if it can be avoided —
  prefer committed tiny fixtures, or skip-with-warning if `ffmpeg` is absent.
- The builder panics rather than returning `Result`, and validates every path
  through `RelPath` as it writes it, so a typo in a test fails at the line that
  wrote it instead of three steps later.
- The fixture is unix-only (symlinks, permission bits). That is deliberate and
  documented; it is what the playlist handling depends on.
